Assessment System Documentation

Overview

The assessment system in Socrates is a modular JavaScript framework that handles quizzes, tests, and assessments. It provides features like auto-saving, section navigation, progress tracking, and submission handling. This document explains how the components work together and how they integrate with the Google Apps Script backend.

Component Architecture

Core Files and Dependencies

assessment-error.js       # Error handling framework (load first)
assessment-sections.js    # Section management for multi-page assessments
assessment-storage.js     # Auto-saving and data persistence
assessment-utils.js       # Common utilities and validation
assessment-submit.js      # Form submission handling
assessment-md.js          # Markdown-specific integration
assessment-loader.js      # JSON-based assessment loading
assessment-glue.js        # Integration between components
assessment-init.js        # Coordinated initialization
password-reappearance.js  # Password screen handling after submission
mathjax-config.js         # Configuration for MathJax rendering in assessments

Load Order: Files must be included in dependency order. The error handling system should be loaded first, and the initialization script last.

Module Responsibilities

Error Handling (assessment-error.js)

Central error management system that captures and reports errors both to the console and to users. It prevents silent failures that could disrupt assessment completion.

  • window.assessmentErrors.report(source, error, context) - Reports errors with source tracking
  • window.assessmentErrors.onError(handler) - Registers error handlers
  • window.withErrorHandling(fn, source) - Wraps functions with error handling

Section Management (assessment-sections.js)

Manages multi-page assessments and navigation between sections.

  • window.sections - Array of assessment sections
  • window.currentSection - Current active section index
  • window.sectionFormData - Form data storage by section
  • window.saveSectionData() - Saves data for the current section
  • initializeSections() - Sets up sections from content

Data Storage (assessment-storage.js)

Handles saving and restoring assessment progress.

  • autoSave() - Saves current form state to localStorage
  • checkForSavedProgress() - Checks for and offers to restore saved work
  • restoreFormData(savedData) - Restores saved form data

Form Submission (assessment-submit.js)

Handles form submission to the Google Apps Script backend.

  • submitAssessment(formData) - Sends form data to the server
  • showFallbackSubmissionDialog() - Fallback when submission fails

Initialization (assessment-init.js)

Coordinates the initialization of all assessment components.

  • Sets up error handling, auto-save intervals, and event listeners
  • Performs health checks on the assessment system components
  • Reports status on component availability

Password Reappearance (password-reappearance.js)

Handles showing the password protection screen after an assessment is successfully submitted.

  • Hooks into the submitAssessment function without modifying the original
  • Shows password screen after a short delay following submission
  • Ensures that other students cannot access a completed assessment
  • Uses function wrapping to extend existing functionality

Implementation:

window.submitAssessment = async function(formData) {
  const result = await originalSubmitAssessment(formData);
  
  if (result.success && typeof window.showPasswordAfterSubmission === 'function') {
    setTimeout(function() {
      window.showPasswordAfterSubmission();
    }, 2000);
  }
  
  return result;
};

MathJax Configuration (mathjax-config.js)

Configures MathJax for proper rendering of mathematical notation in assessments.

  • Defines delimiters for inline math: $...$ and \(...\)
  • Defines delimiters for display math: $$...$$ and \[...\]
  • Uses SVG output with global font caching for optimal performance
  • Ensures consistent rendering across all assessment types
  • Critical for proper display of physics and math equations

Configuration:

window.MathJax = {
  tex: {
    inlineMath: [['$', '$'], ['\\(', '\\)']],
    displayMath: [['$$', '$$'], ['\\[', '\\]']]
  },
  svg: { fontCache: 'global' }
};

Integration with Google Apps Script

The assessment system submits data to a Google Apps Script backend (scripts/google-apps-script/quiz-backend.js) which processes submissions and stores them in Google Sheets.

Submission Flow

  1. User completes assessment and clicks Submit
  2. submitAssessment() in assessment-submit.js gathers form data
  3. Data is sent to the Google Apps Script endpoint defined in ASSESSMENT_CONFIG.webAppUrl
  4. Backend script processes the data and stores it in a spreadsheet
  5. Response indicates success/failure and any next steps

Backend Configuration

The Google Apps Script backend URL is configured in:

  • Jekyll _config.yml under google_scripts.quiz_collector
  • Or via a <meta> tag with name="assessment-endpoint"

Data Format

The submission format is a JSON object containing:

  • AssessmentType: Type of assessment (quiz, test, etc.)
  • AssessmentId: Unique identifier for the assessment
  • AssessmentTitle: Human-readable title
  • StudentName: Student’s name
  • ClassPeriod: Student’s class period
  • Question data: Each question’s data with naming convention Q1_Answer, etc.
  • SubmissionTime: ISO timestamp of submission
  • SectionData: (Optional) Data from each section

Backend Validation

The backend performs validation on submissions to ensure:

  • All required fields are present
  • Student information is complete
  • Data format is correct
  • Duplicate submissions are handled appropriately

Error Recovery and Resilience

The system is designed to be resilient to common issues:

  1. Browser Crashes: Auto-save stores progress in localStorage
  2. Network Issues: Fallback submission dialog if network fails
  3. Script Errors: Error handling prevents single errors from breaking the whole assessment
  4. Missing Components: Graceful degradation if certain components fail to load

Debugging and Testing

For testing and development:

  • assessment-submit-debug.js provides verbose logging
  • Local development mode simulates submissions without sending data
  • test-backend-sim.js in Google Apps Script folder can simulate backend responses

Complete Testing Procedure

To thoroughly test the assessment system:

1. Setup Testing Environment

# Build the site with development flag
python scripts/build_site.py --development

2. Test Individual Components

  1. Error Handling: Open browser console and run: 
    window.assessmentErrors.report('TestComponent', new Error('Test error'));

    Should display formatted error in console and UI.

  2. Auto-Save:
    • Open an assessment and enter data
    • Verify localStorage entry created (DevTools → Application → Storage → Local Storage)
    • Close page, reopen, and check “Restore previous work” option appears
  3. Section Navigation:
    • For multi-section assessments, test navigation buttons
    • Verify data persists between section changes
    • Test browser back/forward buttons with section state
  4. Password Reappearance:
    • Complete test assessment with minimal data
    • Submit the assessment
    • Verify password screen reappears after submission (within ~2 seconds)
    • Verify accessing the same URL requires password again
  5. MathJax Integration:
    • Create test assessment with inline math: $E=mc^2$
    • Create test assessment with display math: \(F = G\frac{m_1 m_2}{r^2}\)
    • Verify proper rendering in all sections of the assessment

3. End-to-End Testing

  1. Create a test assessment with:
    • Multiple sections
    • MathJax content
    • Required fields
    • Password protection
  2. Complete the full assessment flow: 
    Access → Password → Complete form → Submit → Verify data → Password reappears
  3. Verify submission data in Google Sheet:
    • Check spreadsheet for correct data format
    • Verify all form fields are present
    • Check timestamps and metadata

4. Error Recovery Testing

  1. Simulate browser crash:
    • Enter data and close tab without submission
    • Reopen and verify data restoration works
  2. Test offline recovery:
    • Disable network connection
    • Attempt submission
    • Verify fallback submission dialog appears
    • Re-enable network and verify submission succeeds
  3. Component failure:
    • Comment out a non-critical component
    • Verify system degrades gracefully
    • Check error logs for appropriate messages

5. Automated Testing Tools

A set of automated testing scripts is available in the scripts/test directory:

# Run all assessment system tests
python scripts/test/run_assessment_tests.py

# Test specific component
python scripts/test/run_assessment_tests.py --component=storage

# Generate test coverage report
python scripts/test/run_assessment_tests.py --coverage

These tests use Playwright for browser automation and verify:

  • Form data persistence
  • Auto-save functionality
  • Section navigation
  • Form submission
  • Password reappearance
  • Error recovery

Troubleshooting Common Issues

Problem Possible Causes Solutions
Auto-save not working localStorage disabled or full Check browser console for storage errors, clear localStorage
Password doesn’t reappear Script loading order issue Ensure password-reappearance.js loads after assessment-submit.js
MathJax equations not rendering Configuration issue or MathJax not loaded Verify mathjax-config.js loaded before MathJax script
Section navigation broken Missing section markers or incorrect structure Check HTML for proper section elements and data attributes
Form submission fails Network issues or backend configuration Check browser network tab, verify Google Apps Script URL

Quick Validation Walkthrough

For a quick test of the entire assessment system after making changes:

  1. Build the site: 
    python scripts/build_site.py --development

  2. Open a test assessment: Navigate to http://localhost:4000/hphys/course/1-motion-in-one-dimension/assessments/quiz-1-1.html (or any available assessment page)

  3. Enter test data:
    • Complete required fields with test data
    • Add data to multiple sections if available
    • Include special characters and math expressions
  4. Test auto-save:
    • Check browser console: localStorage.getItem('assessmentData')
    • Should return a JSON string with form data
    • Refresh page and click “Restore previous work”
  5. Submit the assessment:
    • Click the Submit button
    • For testing, use the debug option in console first: 
      // Enable debug mode before submission
window.ASSESSMENT_DEBUG = true;
    • Check console for submission payload and response
  6. Verify password reappearance:
    • After submission, password screen should reappear
    • Timer in console should show ~2 second delay
  7. Check backend data:
    • Login to Google Sheets and verify data appeared in the correct spreadsheet
    • Check formatting and complete data transfer

This validation takes approximately 5-10 minutes and provides confidence that all systems are working correctly before deploying changes.

Testing New Features or Modifications

When adding new features or modifying existing components, follow these testing procedures:

1. Isolated Component Testing

Before integrating changes into the full system:

// Create a test module in browser console or test file
(function testComponent() {
  // 1. Create minimal DOM structure needed
  const testContainer = document.createElement('div');
  testContainer.innerHTML = `<form id="test-form">
    <input type="text" name="test-input" value="test value">
  </form>`;
  document.body.appendChild(testContainer);
  
  // 2. Run your component code
  // Example: Testing auto-save functionality
  const formData = collectFormData();
  saveToLocalStorage('test-key', formData);
  
  // 3. Verify results
  const retrieved = localStorage.getItem('test-key');
  console.assert(retrieved && JSON.parse(retrieved).length > 0, 
    'Storage test failed');
    
  // 4. Clean up
  document.body.removeChild(testContainer);
  localStorage.removeItem('test-key');
  
  console.log('Component test complete');
})();

2. Integration Testing

After individual component testing:

  1. Create a minimal assessment that uses your modified component
  2. Test with the real DOM structure and event flow
  3. Verify interactions with other assessment components
  4. Ensure error handling properly wraps your new functionality

3. Regression Testing

Always verify that existing functionality still works:

  1. Run the automated test suite
  2. Perform the Quick Validation Walkthrough (see above)
  3. Test on multiple browsers (Chrome, Firefox, Safari)
  4. Test with keyboard-only navigation for accessibility

4. Version Deployment Testing

When ready to deploy:

  1. Create a version tag for the assessment system files
  2. Update the README.md with any API changes
  3. Test on the staging environment
  4. Perform a final validation walkthrough

Testing Summary

The assessment system requires multiple levels of testing to ensure reliability:

Testing Level Focus Tools
Unit Testing Individual components Browser console, isolated tests
Integration Testing Component interactions Test assessments, browser tools
System Testing End-to-end behavior Manual walkthroughs, automated tests
Regression Testing Maintaining functionality Automated test suite

Testing Priority Order:

  1. Form data collection and submission (core functionality)
  2. Error handling and recovery (resilience)
  3. Auto-save and data persistence (data protection)
  4. Section navigation (usability)
  5. MathJax rendering (content display)
  6. Password protection (security)

Always conduct testing on the lowest level (unit) before proceeding to higher levels. Document any issues found and their resolutions in the commit messages or changelog.

Component Integration

Password Protection and MathJax

The integration between password protection, assessment submission, and MathJax provides a complete solution for secure, mathematically-rich assessments:

  1. Initial Access Control: Password protection limits access to authorized students
  2. During Assessment: MathJax renders mathematical notation throughout the assessment
  3. After Submission: Password screen reappears to prevent unauthorized access to completed assessments

This workflow ensures:

  • Mathematical content displays correctly throughout the assessment lifecycle
  • Assessments remain secure before and after completion
  • Students can’t access others’ completed work, even on shared devices

Loading Order Best Practices

For optimal performance and functionality, include these files in the following order:

  1. mathjax-config.js (before MathJax itself loads)
  2. assessment-error.js (error handling framework)
  3. Core assessment files
  4. password-reappearance.js (after assessment-submit.js)
  5. assessment-init.js (initialization must be last)
